# Гига Писарь в браузере

Диктовка голосом прямо на веб-странице, на той же модели GigaAM v3, что и
маковское приложение. Нажали «Диктовать» — говорите — «Стоп»: текст с
пунктуацией встаёт в поле туда, где стоял курсор. Всё считается **на
компьютере человека**: звук никуда не уходит, сервер только отдаёт файлы.

Это перенос ядра `server/giga_core.py` / `swift/*.swift` на JavaScript.
На одних и тех же записях выдаёт тот же текст, что и питоновское ядро
(см. «Сверка»).

## Запуск

```bash
./web/fetch-vendor.sh     # onnxruntime-web и wllama рядом со страницей (23 МБ, один раз)
python3 web/serve.py      # http://localhost:8000
```

Откройте страницу, выберите архив модели `gigaam-v3-onnx-int8.tar.gz`
([скачать, 204 МБ](https://github.com/moznoazachem/giga-pisar-cli/releases/download/v1.0/gigaam-v3-onnx-int8.tar.gz))
кнопкой «Выбрать архив…» или перетащите его на страницу. Браузер
распакует архив и сохранит модель у себя (Cache Storage, ~325 МБ). В
следующий раз она поднимется из хранилища сама, без сети.

Страница должна открываться по **https** или с **localhost**, иначе браузер
не даст ни микрофон, ни хранилище. С `file://` она не работает.

### Выложить на свой сайт

Папка `web/` — обычная статика, сборка не нужна.

- **Модель рядом со страницей.** Положите распакованные файлы в `web/model/`
  или архив как `web/gigaam-v3-onnx-int8.tar.gz`, и появится кнопка
  «Скачать с этого сайта». С GitHub Releases браузер модель скачать не
  может: GitHub не отдаёт файлы релизов чужим страницам (CORS). Поэтому
  без своей копии модели человек выбирает архив с диска.
- **Потоки.** Выставьте заголовки
  `Cross-Origin-Opener-Policy: same-origin` и
  `Cross-Origin-Embedder-Policy: require-corp` (так делает `serve.py`) и
  выложите `web/vendor` (`fetch-vendor.sh`). Тогда распознавание и мозг идут
  в несколько потоков. Без заголовков страница работает в один поток, а без
  `vendor` берёт движки с jsDelivr.
- **Всё сразу:** `sudo bash web/deploy/deploy.sh` на сервере с nginx
  (страница, модели, мозг GigaChat как служба; см. `deploy/STAT.md`).

## Скорость

Chromium, 4 ядра, запись 7,7 с:

| Режим | Время |
|---|---|
| с COOP/COEP, 4 потока | 1,2 с |
| без заголовков, 1 поток | 2,7 с |
| загрузка модели в память | 4–7 с |

## Что внутри

- `index.html`, `app.js`, `app.css`: страница с полем, кнопкой и строкой
  состояния
- `giga/dictation.js`: кнопка → запись → текст в поле (вместо выделения,
  пробелы по краям только там, где слова иначе слипнутся; Esc — отмена).
  Можно подключить к любому своему полю:
  ```js
  import { Engine } from "./giga/engine.js";
  import { attachDictation } from "./giga/dictation.js";
  const engine = new Engine();
  engine.load();                           // модель уже в хранилище браузера
  attachDictation({ field, button, status, engine });
  ```
- `giga/mic.js`: микрофон в родной частоте (AudioWorklet), без шумодава и
  автогромкости; в 16 кГц пересчитывает OfflineAudioContext
- `giga/engine.js` + `giga/worker.js`: модель живёт в Web Worker, страница
  не замирает
- `giga/recognizer.js`: энкодер → жадное декодирование RNN-T, нарезка
  длинных записей по паузам (`giga/audio.js`)
- `giga/features.js`: лог-мел-спектрограмма, шаг в шаг как у numpy
- `giga/tokenizer.js`: кусочки слов SentencePiece → текст
- `giga/model-store.js`: распаковка tar.gz потоком и хранение модели
- `giga/brain.js`: мозг: обращение «Писарь, …», промпты из приложения,
  GigaChat через сервер и Qwen через wllama
- `deploy/`: выкладка на сервер: `deploy.sh`, куски конфига nginx,
  служба `pisar-brain.service`

## Мозг Писаря

Как в приложении: нейронка причёсывает надиктованное.

- «…текст, **Писарь, исправь**» (сократи, переведи на английский, сгладь…)
  в конце диктовки: текст идёт в нейронку с этой командой.
- Выделили текст и продиктовали команду: она выполняется над выделенным.
- Кнопки «Причесать», «Исправить ошибки», «Сократить», «Собрать мысль»,
  «Сгладить», «Деловой стиль», «Перевести на английский» работают над
  выделенным, а без выделения над всем текстом. После правки нейронкой
  можно «Вернуть как было».

Модели на выбор:

| Модель | Где считает | Что нужно |
|---|---|---|
| GigaChat 3.1 (10B-A1.8B, 6,5 ГБ) | на сервере сайта: llama-server за nginx, адрес `/pisar/brain/`. Туда уходит только текст, звук остаётся на компьютере | сервер с ~12 ГБ памяти, `deploy.sh` |
| Qwen3-4B Instruct (1,9 ГБ) | в браузере, через [wllama](https://github.com/ngxson/wllama) (llama.cpp на WebAssembly/WebGPU) | скачивается один раз кнопкой «Скачать»: с сайта (`brain-models/`), иначе с Hugging Face |

| Любая — на компьютере человека | отдельная программа с OpenAI-совместимым API: наш [GigaBrain](../brain-local/README.md) одним файлом, Ollama или LM Studio. Страница ходит к ней по `http://127.0.0.1`, текст на сайт не уходит | 8–32 ГБ памяти по модели; быстрее всего |

GigaChat в браузер не влезает: WebAssembly даёт странице не больше 4 ГБ памяти.
Промпты и команды кнопок — в `web/giga/brain.js` (`DEFAULT_PROMPTS`, `CHIPS`);
в плагине WordPress они редактируются из админки.

## Чего здесь нет (в отличие от приложения)

Клавиши в любой программе и вставки под курсор в чужие окна: страница
пишет только в своё поле. Нет волны у курсора и значка в строке меню.

## Сверка

```bash
(cd web/test && npm install)
python scripts/сверка-web.py <папка-модели> запись.wav [ещё.wav ...]
```

Скрипт гоняет браузерное ядро в Node (тот же onnxruntime-web) и сравнивает
его текст с `server/giga_core.py`. Записи — 16 кГц, моно, 16 бит.
